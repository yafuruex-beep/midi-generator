# Phase 9 Step 8：単音／パワーコード比較

任意実験スクリプトのみを追加し、既存生成器や既定値は変更しない。
Step 7-A（Step 6-Cと同一）の実MIDIから60グループ・106ノートを読み、
単音14／power5二音46（76.667%）を再確認する。

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/create_chord_voicing_auditions.py \
  examples/requests/chorus_chord_voicing.json output/phase9_step8_chord_voicing
```

出力先は新規ディレクトリが必要。ソースをSHA-256で照合し、Aはバイトコピー。
ルートのOn/Off tick・pitch・velocityと補助メッセージを保ち、上声部root+7だけを
追加／削除する。新しいボイシングや奏法キーは使用しない。
全候補のベース・ドラムは原本のバイトコピー。既存A2のルート−24半音追従を再検証。

構成は元の4小節×2の対応を保持するため、各選択単位を2グループのペアにする。
Bの25%目標は15コードだが奇数はこの対応と両立しない。単音中心側に近い14を選び、
単音46/60=76.667%、コード14/60=23.333%。Bは既存上声部の除去だけ。
Cは[4,4,6,1]コード／小節の4小節を反復し、計30コードで50%。
Dは元と同じ46コードを維持。Eマイナー内にroot+7を置けるペアは48グループ分で、
強いvelocity>=96でコード化できる位置は28件しかない。46コードを全て強アクセント
だけへ置くことはできず、18件以上は他の役割を持つ打点になる。

配置の優先順位（品質点ではない）：フレーズ末尾、velocity>=96、小節頭、
次の強アクセントvelocity>=100まで2step以内の先行発音、キック一致、四分拍位置。
重み・閾値は実験requestに明記。固定数・反復単位の下で合計優先度を最大化し、
同点は元の発音順で決定する。ランダム選択なし。
Dでは2/6小節step6へ上声部を追加し、4/8小節step2の上声部を除去する。
強拍の28コードは元から存在し、Dでも保持。比率増加ではなく弱い位置同士の役割変更。

ギタールート52..59、全音52..66、ベース28..35の既存比較範囲とEマイナーを維持。
F#根音54+7=C#となる位置はコード化しない。音源固有の発音可能域は未確認。
音程移動率は50/59=84.746%を全候補で維持する。

音符数とグループ数は異なる：A/Dは106ノート、Bは74、Cは90だが、全て60グループ。
コード連続回数は時間順で連続するpower5グループの数で、休符をまたぐこともある。
キック一致は既存configの35/36と0.04拍許容差を使用し、コードグループ数と
カバーしたキックイベント数を別記する。候補の自動採用はしない。
